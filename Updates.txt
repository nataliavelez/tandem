Session 2026-09-30 — Multiplayer backend fixes 
------------------------------------------------------------

[bug] Security — A client could control ANY agent: the server trusted the agentId
      field in PLAYER_ACTION. The server now looks up the sender's own seat and
      ignores the client-sent agentId (field made optional in the shared type).
      Files: server/src/index.ts, server/src/game/mpeRoom.ts, shared/types.ts

[feature] Rooms — Replaced the single hardcoded global room with a RoomManager.
      Players fill the oldest open room up to REQUIRED_PLAYERS; when it is full a
      new room is created (room_1, room_2, ...). Once a room's first trial starts
      it is locked, so latecomers go to a new room instead of joining mid-game.
      Empty rooms are disposed and their sidecar env is freed. JOIN_ROOM now
      joins a specific open room or returns an ERROR.
      Files: server/src/game/roomManager.ts (new), server/src/index.ts

[bug] Rooms — Extra players beyond capacity were added to the room with
      agentId=null and still counted toward the lobby total. Now impossible:
      a full room is never offered; the player goes to the next room.
      Files: server/src/game/mpeRoom.ts, server/src/game/roomManager.ts

[bug] Ready check — The ready set was global across all players, and a trial
      started as soon as N readies arrived from anyone. Each room now owns its
      ready set and starts only when every seat is filled and every seated
      player is ready. A leaving player's ready is withdrawn.
      Files: server/src/game/mpeRoom.ts, server/src/index.ts

[bug] Tick loop — setInterval(async ...) could run overlapping sidecar steps
      when a step took longer than TICK_MS, delivering states out of order. The
      loop is now serialized (next tick scheduled only after the previous step
      returns), keeps a fixed cadence without bursting to catch up, and logs
      overruns. After 20 consecutive sidecar failures the trial ends with an ERROR
      instead of erroring forever.
      Files: server/src/game/mpeRoom.ts

[bug] Disconnects — A player who disconnected while holding a key left their
      agent executing that action for the rest of the trial (lastActions never
      cleared). Their agent now gets noop and coasts to rest.
      Files: server/src/game/mpeRoom.ts

[bug] Disconnects — A player leaving mid-trial broadcast a phase:"lobby" state
      to the whole room, blanking everyone's game canvas until the next tick.
      Lobby state is no longer broadcast while a trial is running.
      Files: server/src/game/mpeRoom.ts

[bug] Multi-round — stopTrial never reset the env, so a second round started at
      step >= horizon and ended immediately. The env is now reset after every
      trial, and lastActions are cleared between rounds.
      Files: server/src/game/mpeRoom.ts

[bug] Episode IDs — The sidecar hardcoded "e_0001" on reset and "e_0"/"e_1" on
      step, so episodes could not be told apart in the data. Each reset now
      increments a per-env counter (e_0001, e_0002, ...) used by both reset and step.
      Files: sidecar/app.py, sidecar/env_registry.py

[bug] Sidecar memory leak — Envs were never deleted from ENVS. Added
      POST /env/close; rooms call it when disposed (and if a room is disposed
      while its env is still being created).
      Files: sidecar/app.py, server/src/game/sidecarClient.ts, server/src/game/mpeRoom.ts

[perf] Sidecar speed — reset/step were un-jitted JAX calls. Both are now
      jax.jit-compiled per env, with actions passed as int32 so they do not
      retrace. Envs are warmed up at creation (reset + two chained steps; the
      2nd step triggers a recompile because step returns slightly different
      dtypes than reset). Measured: every step 2–3 ms, including the first;
      previously ~185 ms on step 2, causing tick overruns at each room's first trial.
      Files: sidecar/env_registry.py, sidecar/app.py

[bug] Sidecar validation — /env/step with a missing agent crashed with a
      KeyError (500). It now returns 400 listing missing/unknown agents.
      Files: sidecar/app.py

[feature] Config — Added HORIZON (steps per trial) and SEED env vars, and
      maxParticipants is now sent in lobby state.
      Files: server/src/index.ts, server/src/game/mpeRoom.ts

[robustness] Orchestrator — Malformed JSON and handler errors are caught and
      logged separately; sends are skipped on closed sockets.
      Files: server/src/index.ts

[test] Sidecar — Added tests for episode-id increments, missing-agent
      rejection and /env/close. Fixed test_invalid_action_rejected, which now
      sends actions for all agents so it tests the range check. 7/7 pass.
      Files: sidecar/test_sidecar.py

[test] Verified with a headless bot script (7 bots + 1 late joiner, 3/room,
      30-step trials): room splitting, unique seats, room isolation, locking,
      anti-spoofing, sequential steps at ~100 ms cadence, round 2 runs 1..30 with
      new episode id, disconnect → noop, no lobby overwrite mid-trial. 24/24 pass,
      0 tick overruns. (Script not yet committed to the repo.)

[feature] Stable participant identity. The client reads the participant ID
      from the URL (PROLIFIC_PID, participantId or pid), or generates
      "anon_..." and keeps it in sessionStorage, so a refresh keeps the ID
      and a new tab gets a new one (useful for local multi-player testing).
      STUDY_ID / SESSION_ID URL params are passed along as recruitment meta.
      A new HELLO {participantId, meta} message is the first message on every
      connection, and the participant ID is now the player ID everywhere
      (seats, data log). IDs must be 1–64 chars of [A-Za-z0-9_-]. Clients
      that skip HELLO still work, with a random non-resumable "anon_" ID
      (the bot test relies on this).
      Files: client/src/context/participant.ts (new), shared/types.ts,
             server/src/index.ts

[feature] Seat holding + reconnection. A closed socket no longer frees the
      seat. The seat is held for LOBBY_GRACE_MS (default 10 s, room not
      started) or TRIAL_GRACE_MS (default 30 s, group locked). While held,
      the agent gets noop, the player is not counted as ready, and lobby state
      shows them as connected:false. On return the server replies
      SESSION_STATUS:
        resumed (roomId, agentId, running, trialsCompleted), plus the ORIGINAL
                TRIAL_START if a trial is running, so the timer stays in sync
        new     (no seat: never joined, or lobby grace expired)
        ended   (locked-group grace expired, or the session was opened in another tab)
      A participant whose locked-group grace expires is marked ended and
      cannot be placed in a new group. Second tab with the same ID: the new
      connection takes over the seat and the old one is told and closed.
      Files: server/src/game/roomManager.ts, server/src/game/mpeRoom.ts,
             server/src/index.ts, shared/types.ts

[feature] Client auto-reconnect. Before, the client never reconnected after a
      dropped socket. SocketProvider now reconnects with backoff (0.5, 1, 2, 4,
      then every 5 s) and re-sends HELLO, unless the server said the session
      ended. Screens that need the server show a "Connection lost —
      reconnecting…" banner meanwhile.
      Files: client/src/context/SocketProvider.tsx, client/src/context/socketContext.ts,
             client/src/components/engine/TrialEngine.tsx

[feature] Client resume. TrialEngine keeps the timeline index in
      sessionStorage (refresh returns to the same screen) and corrects it from
      SESSION_STATUS:
        resumed + running     → the mpe entry for the trial in progress
        resumed + not running → just past the last completed mpe trial
        new while past the waiting room → back to the waiting room
        ended → a "Session ended" screen
      Trial screens are now keyed by trial id, so consecutive mpe trials
      remount cleanly. advance() is memoized so trial screens no longer
      re-subscribe on every render.
      Files: client/src/components/engine/TrialEngine.tsx

[bug] After a reconnect, WaitingRoom never re-joined or re-sent ready, since
      its "already sent" flags were per component, not per socket. The server
      forgets readiness on disconnect, so the group would never have started.
      The flags now reset when the socket changes.
      Files: client/src/components/trials/WaitingRoom.tsx

[bug] MpeTrial sent TRIAL_READY as soon as the socket changed, which throws
      if the new socket is still connecting. It now waits for "open".
      Files: client/src/components/trials/MpeTrial.tsx

[feature] Per-room data log (JSONL). Each room writes
      <DATA_DIR>/<server start time>_<roomId>.jsonl (default server/data/,

------------------------------------------------------------

[chore] Committed reconnection + data logging as df18237f on branch mpe.

[design] Policy change: if the server can't continue, participants are sent to
      the end of the study and paid, instead of being put into a new group.
      (Replaces the previous "server restart → back to the waiting room"
      behavior, which would have meant repeated rounds and data split across
      runs.)

[feature] SESSION_STATUS "ended" now carries an outcome:
        aborted  - our failure; participant is paid
        dropped  - participant disconnected longer than the grace period
        replaced - study opened in another tab
      Files: shared/types.ts, server/src/index.ts, server/src/game/roomManager.ts

[feature] Room abort. When a room can't continue, MpeRoom.abort() ends the
      study for the whole group (ended/aborted), logs room_aborted, and the
      manager frees the room and remembers everyone as aborted, so a later
      reconnect still lands on the end screen. Triggers:
        - the sidecar was lost mid-trial (20 consecutive failed steps, ~2 s).
          Previously only the trial ended and the group carried on with a
          broken environment.
        - the environment never became available (after MAX_START_RETRIES).
          Previously the room just sent an ERROR and sat there.
      START_RETRY_MS and MAX_START_RETRIES are now env vars (defaults 3000 / 40).
      Files: server/src/game/mpeRoom.ts, server/src/game/roomManager.ts

[feature] Graceful shutdown. On SIGINT/SIGTERM (Ctrl-C, deploy, process
      manager), the server stops accepting connections, aborts every room
      ("The study server was stopped."), sends ended/aborted to every
      connected participant (including those not yet in a room), closes the
      sockets, data logs and sidecar envs, then exits (forced after 5 s).
      MpeRoom.dispose() now returns the same promise on repeat calls, so
      shutdown really waits for env cleanup.
      Files: server/src/index.ts, server/src/game/mpeRoom.ts, server/src/game/roomManager.ts

[feature] Client-side detection, for when the server can't tell anyone (crash,
      machine down). TrialEngine ends the study as aborted when:
        - SESSION_STATUS "new" arrives while past the waiting room (the server
          restarted and lost the group), or
        - the server is unreachable for VITE_SERVER_LOST_TIMEOUT_MS (default
          45 s, longer than the server's 30 s trial grace) on any screen from
          the waiting room on.
      The ending is saved in sessionStorage, so a refresh stays on the end
      screen and can't re-enter a lobby ("replaced" is not saved, so
      refreshing that tab takes the study back).
      Files: client/src/components/engine/TrialEngine.tsx

[feature] Early-end screen + completion links. New EarlyEnd screen:
        aborted  → apology, "you will be paid", and a "Complete study" button
                   to VITE_ABORTED_COMPLETION_URL
        dropped  → "your session ended because…", with a button only if
                   VITE_DROPPED_COMPLETION_URL is set
        replaced → "continue in the other window"
      If no URL is configured, it asks participants to contact the
      researcher (and warns in the console). Settings live in
      client/src/scripts/studyConfig.ts and are set per study in client/.env.
      Use a different Prolific completion code from the normal one, so
      early-ended submissions are easy to find.
      Files: client/src/components/trials/EarlyEnd.tsx (new),
             client/src/scripts/studyConfig.ts (new)

[test] reconnect.js now checks outcomes (replaced, dropped); 29/29 pass, and
      bots.js passes 24/24. Abort scenarios verified with a scratch script

        env never available (MAX_START_RETRIES=3) → all aborted, no trial
        SIGTERM mid-trial → 3 in-room players + 1 not-yet-joined player all

      Server and client typecheck clean. Not verified: client-side detection

Session 2026-10-01 — Per-study payment settings + minimum group size
------------------------------------------------------------

[chore] Committed early-end handling as 8ec91685 on branch mpe.

[design] Payment policy (decided with the PI):
        - Server/environment failure, or the group falling below its minimum
          size → paid (default; configurable per study)
        - Participant leaves / disconnects past the grace period → not paid
          (default; configurable per study)
        - Never got a seat (e.g. still on consent when the server stopped) →
          never paid
      Paid participants are redirected to an outcome-specific completion URL.
      In Prolific, give each outcome its own completion code and set the code's
      action (e.g. approve automatically) so payment needs no manual review.

[feature] Per-study settings file. The server loads STUDY_CONFIG=<file>
      (relative to server/; default server/.env if present) before anything
      reads process.env; shell variables still override the file. If a named
      file is missing, the server refuses to start. server/studies/example.env
      documents every setting (group, game, payment, disconnects,
      infrastructure). Real study files (server/studies/*.env) are gitignored
      because they hold completion codes. On startup the server logs the group
      and payment settings, and warns if an outcome is paid but has no URL.
      Files: server/src/loadEnv.ts (new), server/src/studyConfig.ts (new),
             server/studies/example.env (new), .gitignore, server/src/index.ts

[feature] Payment settings: PAY_ABORTED (default true) + ABORTED_COMPLETION_URL,
      PAY_DROPPED (default false) + DROPPED_COMPLETION_URL (optional, e.g. a
      "request return" code). SESSION_STATUS ended now carries {outcome,
      reason, paid, completionUrl} (EndInfo), all decided by the server.
      Completion URLs moved from the client (VITE_*_COMPLETION_URL, removed)
      to the server, so codes never ship in the client bundle; seated
      participants receive them only when needed.
      Files: shared/types.ts, server/src/studyConfig.ts, server/src/game/*.ts,
             server/src/index.ts, client/src/scripts/studyConfig.ts

[feature] Minimum group size (MIN_GROUP_SIZE, default = REQUIRED_PLAYERS, i.e.
      any drop-out ends the study). Once a group has started, when a drop-out
      (grace expired) leaves fewer than MIN_GROUP_SIZE players, the room aborts
      for everyone remaining ("Too many participants left the group (k of n
      remain)") → paid per PAY_ABORTED. The drop-outs themselves are "dropped"
      (not paid by default). This is also the first dropout policy (roadmap
      step 7): groups no longer continue with idle agents below the minimum.
      Files: server/src/game/roomManager.ts

[feature] ABORT_POLICY message: when a participant gets (or gets back) a seat,
      the server tells them whether an abort is paid and where to go. The
      client saves it in sessionStorage and uses it when it has to end the
      study on its own (server crashed or restarted). No saved policy = never
      seated = not paid.
      Files: shared/types.ts, server/src/index.ts, client/src/context/abortPolicy.ts (new),
             client/src/context/SocketProvider.tsx, client/src/components/engine/TrialEngine.tsx

[feature] Shutdown: participants with a seat get the room's abort (paid per
      PAY_ABORTED); participants without one get an unpaid "study no longer
      available" ending. This also removes the duplicate ended message seated
      players used to get.
      Files: server/src/index.ts, server/src/game/roomManager.ts

[feature] Early-end screen reworked around EndInfo: paid → "not your fault,
      you'll be paid"; dropped → "your session ended because…, please return
      your submission"; never seated → "study no longer available, please
      return your submission". With a completion URL, it redirects
      automatically after 10 s (button to go now).
      Files: client/src/components/trials/EarlyEnd.tsx

[test] New server/test/groupsize.js (npm run test:groupsize): unseated players
      get no abort policy; seated players get it; 1 of 3 drops → group
      continues (min 2); 2nd drops → last player aborted, paid, given the
      completion URL; returning drop-outs → dropped, unpaid; aborted player
      returning → still paid; log has 2 player_dropped + room_aborted. 7/7 pass.
      All tests now share server/test/test.env (STUDY_CONFIG=test/test.env,
      which also exercises the loader). npm run test:all runs bots (24/24),

      waits out the lobby grace before exiting (its held seats were leaking

      Files: server/test/groupsize.js (new), server/test/test.env (new),
             server/test/bots.js, server/test/reconnect.js, server/package.json

Session 2026-10-01 (cont.) — Fix room-creation freeze + data saving fixes
------------------------------------------------------------

[bug] Sidecar — Opening a room froze games already running (steps up to
      643 ms instead of ~30 ms) because every env re-JITted reset/step
      (0.5–2 s per env): JAX caches compilations per function object, and each
      env's bound methods are new objects. The env + jitted reset/step are now
      cached per config (task, agents, landmarks, local_ratio, horizon) and
      shared by every env with that config; envs keep no episode state, so
      sharing is safe. A lock makes simultaneous first creates compile once.
      Re-measured (8 rooms stepping at 10 Hz, 3 bursts of 4 creates): creates
      take 0.01–0.02 s, step latency max 36 ms during bursts.
      Files: sidecar/env_registry.py

[feature] Server warms the sidecar at startup (create + close one env with the
      study's config, retrying for ~1 min while the sidecar starts), so even the
      first room doesn't compile. Logged: "sidecar warmed up in N ms".
      Files: server/src/game/mpeRoom.ts (warmSidecar), server/src/index.ts

[bug] Data — spec.seed was always 0 (it logged key_data(key)[0], which is 0 for
      every PRNGKey). The sidecar now reports the seed the env was created with.
      spec_hash no longer includes the seed, so it identifies the game config
      (same game = same hash, whatever the seed). Old pilot logs have seed 0 and
      a hash computed with seed=0.

[feature] Data — each episode's starting state (step 0) is logged as

[bug] If the reset after a trial failed, the next trial started at the old
